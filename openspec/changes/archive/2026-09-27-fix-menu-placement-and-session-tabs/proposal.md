## Why

两处都是"布局写死、没有按可用空间做决定"造成的：

**行内操作菜单**（集合树与环境列表行末的 `⋯`）位置由 CSS 写死 `top: 100%`，方向永远向下；而它的宿主是 `overflow: auto` 的滚动容器（`.tree-root`、`.env-list`），绝对定位的后代一样会被裁。于是最底部的节点打开菜单时，菜单从行底部往下长、直接超出侧栏可视区——看起来像"点不出来"。同一个问题在 `Dropdown` 里已经解过：它 portal 到文档根、`position: fixed` 自定位，并在展开前比较上下两侧的可用空间决定朝哪边。行内菜单没有走这套，两处菜单的实现因此各是各的。

**会话标签栏**则是一处 CSS 撑开导致的两个症状：`.session-tab` 有 `min-width: 96px`，内容不足的标签被抹平到 96px，而标签内没有任何元素吸收多出来的宽度——多出的部分**全落在关闭入口之后**。请求标签因为方法徽标较长，内容通常已经超过 96px，于是几乎看不到同一现象。这让"× 后面空着一大段"与"集合/目录/请求标签表现不一致"成为**同一个原因的两个表现**。标签内部另有一处：种类图标（12×12）、方法徽标（11px 文本）与名称（12px 文本）由 `align-items: center` 按**盒子**居中，但三者的盒高各不相同，看起来并不齐平。

**树上的操作则缺两条通路**。请求节点的菜单里有「重命名」与「复制」，文件夹节点只有「重命名」——**「复制一个目录」这件事在界面上根本不存在**，想复制一棵子树只能手工重建，而目录复制的语义（连同子文件夹与请求递归复制、落在同一个父级）恰恰是集合树最需要的能力之一。同时，已有的「复制」与未保存改动的关系没有定义：它直接从数据库取源请求，编辑器里尚未保存的改动会被**静默丢掉**——用户看到的是"复制出来的是旧内容"，而不是任何提示。这处沉默与本次的主题同源：界面没有按用户的实际状态做决定（前两处是按可用空间，这里按是否存在未保存改动）。

## What Changes

- **行内操作菜单与下拉菜单共用同一套浮层定位**：垂直方向按展开前的可用空间决定向上还是向下（下方不足且上方更宽裕时向上），并作为覆盖层渲染，不再被所在滚动容器裁剪。集合树与环境列表两处菜单一起生效。
- **会话标签的宽度由内容决定**：去掉用于撑开短标签的固定最小宽度，把剩余宽度交给名称吸收；关闭入口贴在标签末尾，其后不再留空白。三类标签（请求 / 集合 / 目录）由此走同一套宽度规则。
- **标签内部统一盒高**：种类图标、方法徽标与关闭入口落在同一个盒高上，使"按盒高居中"等价于"视觉齐平"。
- **树操作获得键盘入口**：`Ctrl+D` 复制、`Ctrl+E` 重命名，作用于**当前点击（即当前打开）的实体**；焦点位于输入框或代码编辑器内时 SHALL NOT 触发（与 `Ctrl+S` 相反——`Ctrl+E` 在 macOS 上是文本框的行尾键）；菜单项在右侧标出对应键位。
- **目录可以复制**：文件夹节点的菜单新增「复制」，新目录落在**同一个父级**下、名字沿用既有的 `{name} 副本`，其下的子文件夹与请求递归复制，复制完成后新目录展开。
- **未保存的改动会挡住复制**：被复制的请求自身、或（复制目录时）其递归范围内任一请求存在未保存改动时，复制 SHALL NOT 执行，改为弹出一个**独立的模态提示**并点名是哪些请求。菜单路径与快捷键路径共用同一条判定。

**不做**（有意排除）：

- **不做集合的复制**。本次的对象是"目录"，而集合级复制会连带集合变量表（`scope = collection` 的行）一起复制——副本的变量是否独立、取值是否重新加密属于另一个范围。
- **不做菜单的键盘导航**（方向键在菜单项间移动、回车触发）。
- **不让快捷键作用于鼠标悬停的那一行**：树的悬停态在指针离开时即清空，按下快捷键前还必须保证指针停在树上，不是可依赖的作用对象。

- **不改激活标签的字重**。`.session-tab.active { font-weight: 500 }` 与 spec 中「非激活标签与激活标签 SHALL 等宽」存在既存冲突（字重变化会改变宽度），本次不碰标签的视觉权重，只改宽度规则；这处偏差另行处理。
- **不变更标签的其余交互**：中键关闭、未保存指示与关闭入口共用一格、标签栏横向滚动、标签上的按下不触发窗口拖拽——全部保持原样。
- **不统一图标系统**（窗口控制的手写 SVG、工具栏的文本字符仍各是各的），本次只让标签内的三者盒高一致。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `ui-layout`: 新增「会话标签的宽度与内部对齐」——标签宽度由内容决定、关闭入口贴在标签末尾、种类标记与名称视觉齐平。
- `ui-layout`: 新增「树操作的快捷键」「复制请求与目录」「未保存的改动阻止复制」——键盘入口的作用对象与生效条件、目录复制的范围与命名、复制被未保存改动挡下时的呈现。
- `ui-polish`: 新增「浮层在垂直方向的定位」——下拉菜单与行内操作菜单共用同一套垂直适应规则：下方空间不足且上方更宽裕时向上展开，且不被所在容器裁剪。

## Impact

- **代码**：`src/components/NodeMenu.tsx`（改用共用定位）；`src/App.css`（`.node-menu` 的定位方式、`.session-tab` 及其内部元素）；若把 `Dropdown` 里那段定位抽成共用实现，则会新增一个 `src/lib/` 下的 hook，`Dropdown.tsx` 与 `NodeMenu.tsx` 各自接线。
- **代码**（树操作这部分）：`src/App.tsx`（快捷键分支与作用对象解析、复制前的未保存判定与模态提示、复制后的展开收尾）；`src/components/WorkspaceTree.tsx`（文件夹菜单新增「复制」、菜单项标出键位、就地改名的命令式入口与祖先链展开）；`src/components/NodeMenu.tsx`（菜单项支持键位文案）；Rust 侧新增文件夹递归复制命令（`src-tauri/src/storage/workspace.rs`、`src-tauri/src/commands.rs` 的命令体与 `src-tauri/src/lib.rs` 的 handler 清单）。
- **行为变化**（树操作）：文件夹可以整棵复制；复制在存在未保存改动时从「静默复制旧内容」变为「拒绝并弹出提示」；复制与重命名获得键盘入口。
- **行为变化**（均为修正，不是回归）：行内菜单在最底部节点上改为向上展开；菜单不再被滚动容器裁掉；标签宽度不再被 96px 抹平——同样名字长度的标签变窄，同一行能容纳更多标签；关闭入口之后不再有空白。
- **既有测试**：`tests/` 与 `tests-browser/` 中若有断言菜单或标签几何（宽度、位置、可见性）的用例，需要按新行为复核；标签宽度变化可能影响依赖"标签行宽度"的既有断言。
- **无**数据、依赖、schema 变化。
