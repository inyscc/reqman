# Design

## Context

动机见 `proposal.md - Why`。与设计相关的现状只有两条：

- 「保存全文」是响应头里唯一的动作按钮（`src/components/ResponsePanel.tsx`），它调用 `App` 的 `saveFullResponse` → 前端命令 `responseSaveFull` → 后端命令 `response_save_full`。这条链上没有第二个调用者，而它也是**被截断的大响应取回完整正文的唯一界面入口**。
- 请求编辑器的页签选择存在每个会话标签对象的 `innerTab` 字段上，组件是受控的；默认值以 `'params'` 字面量散落在 `src/App.tsx` 的五个位置（打开、新建、复制、工作区恢复、渲染兜底）。请求标签的持久化形态里**不带** `innerTab`（`src/lib/sessionTabs.ts`），因此重启后一律回到默认值。

## Goals / Non-Goals

**Goals:**

- 把响应头收成"只有标签"的一行，并按用户要求移除完整正文的界面取回入口。
- 让"打开请求落在哪一页"成为一个可被规格判定的行为，而不是散落的字面量。

**Non-Goals:**

- 不做请求页签选择的持久化：重启后仍落在默认值，这是本变更接受的既有限制，不顺手改。
- 不改集合实体面板的默认页签——那条由 `ui-layout`「集合面板的变量与脚本站签」明文规定为「变量」页，与本变更的请求编辑器无关。
- 不改响应头的标签组构成、发送态遮罩与进度线。

## Decisions

### D1 移除范围：删界面入口与前端连线，保留后端命令

删除 `ResponsePanel` 里的按钮、它的 `onSaveFull` prop，以及 `App` 里只服务于它的 `saveFullResponse`。**保留**后端 `response_save_full` 命令与其在 `security_audit.rs` 白名单里的条目。

理由：这条命令是一条能力出口，不是界面细节。清掉它必须同时改审计白名单的期望名单，将来若把取回入口挂到别处（例如响应正文工具条最右端）又要再加回来——两次改动换来的只是"没有无调用者的命令"。而保留它不产生任何用户可见面，也不扩大能力类别（它本来就已登记在案）。

**替代方案（否）**：一并清掉后端命令。省下的是一条死命令，代价是动安全审计名单，得不偿失。

**替代方案（否）**：只删按钮、保留 prop 与 `saveFullResponse`。留下无调用者的 prop 会在下次读这个文件时被当成"仍在使用的线索"，也过不了本仓库"不留死代码"的既有纪律（前端这一侧没有保留的理由——它不是能力出口）。

### D2 截断提示只说事实，不再承诺动作

被截断时那条 warn 改为只陈述「界面只持有前 N MB」，删掉指向按钮的半句。

理由：界面上不存在的东西不能被文案承诺。`http-engine`「大响应保护」只要求"呈现完整元数据、明确标示响应已被截断"，**未要求**提供取回动作，因此移除入口不违反既有规格；真正需要同步的只有 `ui-layout`「发送中的响应区反馈」里把「保存全文」写进"发送中照常可用"的那半句。

**替代方案（否）**：把取回入口挪到响应正文工具条。本变更的目的正是减少界面上的动作项，且用户的要求是"干掉这个按钮"——挪位置属于扩大范围。

### D3 默认页签收敛为一个常量，且只回答「首次落在哪一页」

新增 `DEFAULT_REQUEST_TAB: Tab = 'body'`，替换五处 `'params'` 字面量：`openRequest`（打开/展开已存在请求）、`createRequest`（新建）、`duplicateRequestById`（复制）、工作区恢复 effect、渲染层的 `innerTab ?? 'params'` 兜底。

已打开标签的页签记忆**保持不变**：`openRequest` 对已开标签直接聚焦、不重载草稿的既有行为不动，因此"切走再切回"仍停在它自己的页签。规格里那个新增需求据此写成两段——默认值 + 不覆盖既有记忆——避免实现时把它读成"每次聚焦都重置为 Body"。

**替代方案（否）**：把「默认停在 Body」并入既有 requirement「请求标签命名」。那条只管标签的命名与顺序，把"默认停在哪个页签"塞进去会让它的判据从"文案与顺序"变成两类不相干的事。

**替代方案（否）**：顺手把请求页签选择持久化。它与本变更的诉求无关，且会让"重启后恢复"这一条从"落在默认值"变成"落在上次的页签"，把一个小的确定性改动扩成一个需要迁移与守卫的持久化改动。

## Risks / Trade-offs

- [截断响应不再有任何界面入口能取回完整正文] → 本变更有意接受的取舍，已写入 proposal；后端通道保留，将来若要让用户取回，不需要改后端。
- [默认页签从 Params 变 Body 会让既有断言里"打开后看到 Params"的隐式前提失效] → 实现时先 grep `tests/` 与 `tests-browser/` 中依赖打开后页签的用例，逐条核对；`npx tsc --noEmit`、`npm test` 与浏览器用例全绿才算完成。
- [五处字面量收敛时漏掉一处，导致某条入口仍落在 Params] → 收尾用 grep `'params'` 校验 `src/App.tsx` 内不再有裸字面量，新增用例覆盖四条入口（新建 / 展开 / 复制 / 恢复）。

## Migration Plan

无数据迁移：变更只涉及界面行为与一处文案，不涉及存储格式、不涉及既有数据的读取含义。
