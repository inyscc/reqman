## Context

curl 生成能力已经完备且被规格覆盖：后端 `curl_export`（`src-tauri/src/interchange/curl.rs`）把**解析后**的请求序列化，取真实取值（含 secret 明文，见那里的 design D9 与 Rust 测试「命令本身取真实值」），本地文件位置给占位符并把原因放进 `warnings`；前端唯一的入口在「导入 / 导出」模态里（`ImportExportPanel.tsx`），输出渲染成只读的 `pre`。

请求带（identity 行 + 地址栏 + 解析预览条）是这次改动之前刚抬到主区顶部的通栏区域，因此「与请求同屏的一次点击」有现成的落点。

## Goals / Non-Goals

**Goals:**

- 让「拿到当前请求的 curl」变成一次点击，且拿到的文本可以就地改（因为生成结果里本来就有需要人替换的位置）。
- 明确它的语义边界：这是命令的**快照**，不是请求的另一种编辑形态。

**Non-Goals:**

- 把 curl 文本解析回请求（需要 curl 解析器：shell 引号、`-F`/`-d`/`--data-binary`/认证头各有形态，且往返有损）。
- 改动生成口径（尤其 secret 的取值方式）与后端。
- 整集合批量导出。

## Decisions

### D1 快照语义：生成一次、不自动跟随、只有「重新生成」能覆盖

展开时生成一次；请求在展开期间变化不覆盖文本块。「自动跟随」看起来更聪明，但用户一旦在框里改了东西，下一次请求变化就会把它冲掉——而「能改」正是这个功能的理由。收起再展开即重新生成（组件卸载即重置），避免一个看不见的脏状态继续存在。

*备选与拒绝理由*：自动跟随 + 编辑时暂停跟随——要维护「用户是否改过」的脏标记，行为难以预期（同样的操作有时跟随有时不跟随）；双向回写（D1 的反面）需要 curl 解析器，见 Non-Goals。

### D2 复用 `curl_export`，生成发生在点击与「重新生成」时

不新增后端命令、不改生成口径。生成不在每次编辑时触发（不同于解析预览条的防抖链路）：它的触发点是用户的显式动作，这样也顺带避免了「生成频率随输入变化」带来的抖动与日志噪音。

*连带决定*：模态里那处入口保留原样；两处调用同一个命令，因此同一请求的命令必然一致。

### D3 入口位置与形态：请求带右侧栏尾，常驻可见

入口是带文字标签的按钮（`cURL`），放在请求带的身份行右端、与「另存为 / 删除」同区但**常驻可见**（那两个是按需显现的次要操作，这个是功能入口，隐藏会让人找不到）。展开态用 `aria-expanded` 标记，并复用现有的 `.tabs` 那种「比所在托盘高一档」的活动态表达。

*备选与拒绝理由*：与「发送」并排放在地址栏行——会和主操作抢视觉重心；放进集合树的行菜单——那要求先选中请求，与「一次点击」相悖。

### D4 文本块：可编辑的多行文本 + 两个动作

等宽多行文本框（`textarea`），内容即命令原文；下方一行是动作与提示：「重新生成」「复制」，以及生成结果给出的 warnings（例如哪个字段引用了本地文件需要替换）。文本块设最大高度、超出内部滚动——命令可能很长（多请求头 + 多行正文），不能让它把分栏区挤没。

### D5 剪贴板：先验 `navigator.clipboard`，失败则加插件

Tauri 的 WebView2 属安全上下文、点击是用户手势，因此 `navigator.clipboard.writeText` 应当可用；但这是**未验证的假设**，所以列为第一个任务：真环境点一次、确认真拿到内容。不可用时的退路是加 `@tauri-apps/plugin-clipboard-manager`（新增依赖，届时再评估），而不是静默失败——复制动作必须给出可见反馈。

## Risks / Trade-offs

- [命令里的 secret 明文现在会停在一个常驻可见、可编辑的框里，曝光面比模态里的 `pre` 更大] → 口径未变（既有的 design D9 决定），因此本变更不处理；如果将来要改为掩码 + 提示替换，需要同时改 `curl.rs` 的那条 Rust 测试与 `postman-interchange`「导出 curl」需求——那是一次独立的口径变更。
- [剪贴板 API 可能被运行环境拒绝] → 第一个任务先验证；失败则加插件或退化为「全选文本」并明确提示。
- [长命令把请求带撑高、挤压分栏区] → 文本块设最大高度并在内部滚动；请求带本身是 `auto` 行，不会让分栏区负高。
- [用户在文本块里的编辑被误当成请求数据] → 规格与单测双向钉住：改文本既不改 `draft`，也不进入保存载荷。

## Migration Plan

无迁移：不加字段、不加命令、不改存储；回滚只需撤掉请求带上的入口与文本块，既有的模态入口全程可用。
