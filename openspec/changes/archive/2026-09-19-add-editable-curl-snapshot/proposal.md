## Why

curl 命令目前只能从「导入 / 导出」模态里取到，而且输出是一段**只读**的 `pre`。但命令里本来就有必须手改的位置——请求体引用本地文件时是 `@<需自行替换为本地文件路径>` 占位符，临时想换个 token 或去掉某个头也得改——用户只能把整段抄到别处再改。而它本来就该和请求同屏：生成依据是当前这条请求。

## What Changes

- **请求带上新增「cURL」入口**：点击一次，在地址栏下方展开一块**可编辑**的 curl 文本（等宽、多行文本框）；再点一次收起。
- **快照语义**：展开时生成一次，之后**不自动跟随**请求变化（自动跟随会在用户编辑时把内容冲掉）；提供显式的「重新生成」用当前请求覆盖文本。收起再展开即重新生成（不保留上一次的编辑）。
- **编辑不回写请求**：文本框是命令的一份快照，改它不影响请求数据，也不影响保存的内容。
- **沿用既有的生成契约**：复用 `curl_export`（解析后的真实取值、本地文件占位符、`warnings`、`contains_secret`），后端与存储**零改动**；「导入 / 导出」模态里的既有入口保留。
- **「复制」动作**：复制的是文本框**当前**的内容（即用户改过的那份），而不是生成时的原文。
- **非目标**：把 curl 文本解析回请求（需要 curl 解析器，shell 引号与各种参数形态都有损，是另一档工作量）；整集合批量导出；改动 secret 在命令中的取值口径。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `ui-layout`: 新增「请求带上的 cURL 快照」需求——入口、可编辑文本块、快照与重新生成语义、复制、收起行为；并明确它不写回请求。

## Impact

- **前端**：`src/App.tsx`（把入口与文本块接进请求带）、`src/components/RequestEditor.tsx`（请求带内新控件，或新增一个组件）、`src/App.css`；生成走既有的 `client.curlExport`，无新增命令。
- **剪贴板**：优先用 `navigator.clipboard.writeText`（Tauri 的 WebView2 属安全上下文，点击是用户手势）；若被拒则加 Tauri 的 clipboard 插件——动手第一步先在真环境验证，不预设它可用。
- **不变**：`curl_export` 的生成口径与它的 Rust 测试、导入导出模态的既有入口、存储与数据模型。
- **测试**：新增单测覆盖「一次点击展开」「编辑不影响请求」「重新生成覆盖编辑」「复制当前内容」「收起再展开重新生成」「未选中请求时没有入口」。
