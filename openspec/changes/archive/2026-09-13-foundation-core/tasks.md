## 2. 存储层

- [x] 2.1 定义 schema v1：工作区、集合、可递归文件夹、请求、环境、变量（含初始值与当前值两列）、以及支撑条目顺序的字段。验证：全新环境中启动应用后数据库初始化成功，`user_version` 为 1，重复启动幂等无副作用。
- [x] 2.2 实现基于 `user_version` 的有序迁移执行器：每步一个事务，迁移前复制数据库文件为备份，成功后清理备份。验证：单测中注入一个必定失败的迁移步骤，断言原数据仍可读、无半迁移状态、备份文件存在；注入成功步骤时断言版本号推进且备份被清理。
- [x] 2.3 实现工作区命令：列表、创建、重命名、删除、切换。验证：单测在创建两个工作区后分别写入内容，断言彼此不可见、不串改；首次启动场景断言存在默认工作区。
- [x] 2.4 实现集合/文件夹/请求的创建、重命名、删除、复制、移动与顺序持久化。验证：单测构造多层嵌套并在重开后断言层级、归属与顺序完全一致；断言同级重名条目各自独立存取。
- [x] 2.5 实现请求的保存、自动保存与另存为。验证：单测对含 query、headers、raw body 与认证的请求做保存-重开往返，逐字段比对一致；另存为后修改其中一份断言另一份不受影响。
- [x] 2.6 实现环境与变量命令，含活动环境切换，并保证初始值与当前值的更新互相独立。验证：单测断言改当前值后初始值不变、反向亦然；断言环境仅在其所属工作区可见。
- [x] 2.7 实现数据备份导出与从备份恢复。验证：集成测试执行导出→清空本地数据→恢复，断言工作区、集合、请求、环境与变量与备份时一致。
- [x] 2.8 实现工作区级全局变量、应用级设置与随环境保存的环境级代理配置的持久化，并暴露对应的 `globals_*` 与 `settings_*` 命令。验证：单测断言某工作区的全局变量在其下不同集合的请求中均可解析且重开后保留；断言全局代理配置重开后仍生效；断言环境级代理随其环境存取。

## 3. 密钥与日志脱敏

- [x] 3.1 定义密钥提供者接口，提供测试用的内存实现与生产用的操作系统凭据库实现；凭据库不可用时进入降级态并拒绝持久化 secret 值。验证：在无凭据库会话的 Linux 环境上加密相关单测全部通过；模拟凭据库缺失时断言命令返回明确的降级错误且数据库文件中不含明文。
- [x] 3.2 实现 secret 变量值的 AEAD 加密落库与解密读取。验证：写入一个可识别的明文值后直接用检索工具读取数据库文件，断言检索不到该明文；断言解密失败时返回「不可读」状态而非空值或静默清空。
- [x] 3.3 实现日志脱敏单一出口：按头名黑名单做字段级脱敏、对已知 secret 值做值级清洗，且请求与响应正文默认不写入日志。验证：单测断言授权头、Cookie、Set-Cookie 与 API Key 类字段被掩码；断言以某个 secret 值作为普通字段出现时同样被清洗；断言一次完整请求-响应流程的日志中不含正文内容。

## 4. 变量引擎

- [x] 4.1 实现作用域快照与优先级解析，顺序为 `local > data > environment > collection > global`。验证：单测覆盖同名变量在各作用域组合下的取值，并单独覆盖「高优先级作用域存在但未定义该名称」时取次优先级的场景。
- [x] 4.2 实现 `{{name}}` 替换与路径变量填充。验证：单测断言 `/users/:id` 与 `/users/{{id}}` 在相同取值下产出同一 URL；断言 URL、query、headers、body、认证字段中的占位符均被替换。
- [x] 4.3 实现动态变量（唯一标识符、时间戳、随机整数、随机 UUID、随机姓名、随机邮箱）。验证：单测断言同一次请求内两次引用同一动态变量得到互不相同的合法值；断言随机整数落在约定区间；断言用户作用域同名条目不会遮蔽动态变量。
- [x] 4.4 实现未解析诊断输出。验证：单测断言任何作用域都未定义的变量被列入诊断清单，且替换结果中保留 `{{name}}` 原文而非空串。
- [x] 4.5 暴露仅做解析、不发送的预览命令，供界面提示未解析变量。验证：同一请求输入下，预览命令与真实发送路径产出的替换结果逐字段一致。

## 5. 网络层

- [x] 5.1 实现请求模型与执行路径，同时支持按已保存请求 id 执行与按内联载荷执行，两条入口共用同一执行实现。验证：对本地测试服务器分别经两条入口发送等价请求，断言服务端收到的请求一致。
- [x] 5.2 实现全部请求体类型：无正文、raw（JSON/XML/HTML/Text/JavaScript）、多段表单（含文件字段）、URL 编码表单、二进制。验证：对本地测试服务器逐类型断言收到的内容类型与原始字节符合预期；断言从 raw 切换到无正文后不携带原正文。
- [x] 5.3 实现文件选择的一次性句柄机制：选择动作产生句柄，发送命令只接受句柄。验证：单测断言发送命令拒绝路径字符串入参；断言同一句柄不可被重复使用。
- [x] 5.4 实现代理求解：请求 > 环境 > 全局的优先级、HTTP/HTTPS 与 SOCKS5、代理认证、`no_proxy` 白名单，以及跟随系统代理。验证：单测断言请求级配置覆盖环境级、环境级覆盖全局；断言命中白名单的目标未挂代理；断言选择跟随系统代理时读取的是请求时刻的系统设置。
- [x] 5.5 实现认证方式：无认证、继承父级、Basic、Bearer Token、API Key（可选放入头或查询参数），认证字段支持变量引用。验证：对本地测试服务器断言实际发出的头或查询串符合所选方式；单独覆盖「请求继承集合认证」的场景；断言凭据不以明文进入日志。
- [x] 5.6 实现请求级网络设置：超时、重定向开关、证书校验开关、编码、协议版本。验证：对自签证书目标断言默认连接失败并给出证书错误；断言关闭校验后可连接且该响应带警示标记；断言超时设置生效并产生可区分的超时结果。
- [x] 5.7 实现响应处理：状态码、耗时、体积元数据，原始/格式化/预览三种视图，以及 JSON/XML/HTML/图片/二进制的分别呈现。验证：对本地测试服务器断言各元数据正确；断言合法 JSON 在格式化视图缩进而原始视图保持原样。
- [x] 5.8 实现响应体积上限、截断、分段取回与全文流式保存。验证：对本地测试服务器返回的超限响应断言元数据完整、正文被标记为截断、且超出格式化阈值时结构化视图不可用；断言全文可经后端保存到用户选定位置；断言界面在接收大响应期间仍可操作。
- [x] 5.9 实现非法目标与异常的呈现：区分超时、域名解析失败、连接被拒、证书错误与代理错误。验证：单测或集成测试对每种失败构造目标，断言返回不同的分类码而非笼统错误。

## 待补验证（延后，非遗漏）

7.3 与 7.5 的行为验证需要开发环境不具备的条件；用例与步骤已就位，留待具备条件时执行，在此之前保持未勾选。

- **7.3 不可信响应的渲染隔离** — 需要能安装浏览器的环境（本机无法完成 Playwright 的浏览器下载，且系统无浏览器）。用例：`tests-browser/sandbox.spec.ts`，执行 `npx playwright install chromium && npm run test:browser`。该用例含**正对照**：同一载荷在授予 `allow-scripts` 时脚本必须被执行，因此它的通过是有意义的而非恒真。隔离的结构性前提已由自动化覆盖——前端用例断言承载方式为 `sandbox=""`（无 `allow-scripts` / `allow-same-origin`），安全审计断言 CSP 的 `frame-src` 受限。
- **7.5 Windows 构建与冒烟** — 需要 Windows 机器或 runner。步骤：`npm run tauri build` 并断言安装包产物存在 → 启动产物 → 断言 `%APPDATA%\cc.inys.reqman\reqman.db` 已生成且 `PRAGMA user_version = 1` → 执行 7.1 的端到端流程。第三步是关键：应用只要能在 Windows 上启动并完成存储初始化，就说明 Rust 侧、迁移、密钥初始化与窗口创建整条链路可用，不依赖人工点击。

**有意不做自动化的部分**：原生系统文件/保存对话框（`pick_upload_file`、`backup_export`、`backup_restore`、`response_save_full`）。驱动原生对话框成本高、稳定性差；当前分层是「对话框为薄包装 + 其下层逻辑全部有测试」，且路径从不来自前端。若将来确有需要，做法是把对话框抽象为可注入接口并以假实现替换。
