## Why

请求编辑器最需要宽度的那一行（方法 + URL + 发送）被主区的左右分栏切在半边，而地址栏与请求的身份信息本质上是整个请求区的头部、不属于某一列。与此同时，环境变量的值只有一条可见路径——切到 Environments tab，而那条路径会把正在看的请求从主区顶掉；环境列表与键值表的观感也与同类工具差距明显（灰底输入框堆满表格、吸顶表头看不出吸顶、环境行挤在 22px 里）。三处都在同一批文件上，分开做只会互相踩。

## What Changes

- **请求带抬到主区顶部横跨整宽**：请求面板头（集合名 › 请求名 + 未保存/保存/另存为/删除）、地址栏（方法 + URL + 发送）、解析预览条构成一条通栏带；左右分栏只作用于请求带以下的区域。分栏比例、分隔线、比例下限的语义**不变**（仍是宽度比、仍按工作区持久化）。
- **新增环境变量的只读浮层**：锚在会话标签行的环境选择器下方，覆盖在内容之上。分两段——本请求实际用到的变量（名称 + 当前值 + 已解析/未解析）与当前环境 / Globals 的全部变量。只读：secret 以掩码呈现且不提供揭示入口，改动量仍然回主区的环境编辑器（从浮层进入）。浮层**不改变任何栏的布局**。
- **环境列表观感**：行高从 22px 提到约 32px（解除与集合树同密度这条隐性约定）、活跃态改为 ✓ + 浅灰整行底（去掉绿色「使用中」徽标与左侧强调竖条）、Globals 行去掉副标题、工具栏增加搜索框并与「新建环境」并排。
- **请求体类型改为横排单选**：`none / form-data / x-www-form-urlencoded / raw / binary` 一排 chip-radio，选中项以主色标识；raw 的语言下拉内联在同一行右端，仅在 raw 时出现。切换类型清掉其它类型残留内容的既有行为不变。
- **键值表表面与列**：单元格去掉灰底与四边框，只保留行底发丝线，hover / 聚焦时才给边界；表头的表面与吸顶真正可辨识；Params、Headers、x-www-form-urlencoded 三张表增加可就地编辑的 Description 列（幽灵行同步补一格）。由此**空行清洗分两档**：保留判定（保存与打开）以「名称、值、描述三者皆空」为准，发出判定仍要求名称非空——只填了描述的行会被保留下来，但不会进入实际请求；参数表按查询串同步重建时也 SHALL NOT 丢掉这类行。变量表只做表面——它没有描述字段，且其值必须是可就地编辑的输入框。
- **非目标**：GraphQL 请求体（`BodyKind` 无此类型，属能力扩展，另立变更）；form-data 的描述列（该表的 `description` 字段已被文件名占用，拆开牵到数据模型与导入导出）；深色主题；变量表的 Description 列。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `ui-layout`: 请求面板头、地址栏与解析预览条的位置改为主区顶部的通栏请求带（既有「请求面板头的身份与操作」「地址栏与解析预览条」「主区左右分栏与可调比例」三条需求随之收窄/改写）；新增「环境变量的只读浮层」需求；Environments tab 的环境列表观感（行高、活跃态、搜索框）；请求体类型的控件形态；键值表的列结构（Description 列）。
- `ui-polish`: 「表格轻量化与 hover 高亮」补齐单元格表面与吸顶表头的可见性要求，并把变量表纳入同一套表面规则。
- `http-engine`: 「URL 与查询参数」补一条：按查询串重建参数列表时 SHALL NOT 丢弃没有对应查询串的行（例如只带描述的行）。

## Impact

- **前端**：`src/App.tsx`（主区网格分层、请求带）、`src/components/RequestEditor.tsx`（拆分请求带与列内容、chip-radio、Description 列）、`src/components/EnvironmentsPanel.tsx`、`src/components/VariablesPanel.tsx`、新增的变量浮层组件、`src/App.css`、`src/lib/types.ts`、`src/lib/rows.ts`（空行清洗分两档）、`src/lib/url.ts`（按查询串重建时保留不对应查询串的行）。
- **后端**：`RequestPreview` 增加 `used`（本请求实际用到的变量名）。该值在解析阶段已经算出（`ResolvedRequest.used`），目前只是没有送出前端边界。
- **不变**：存储与数据表、导入导出映射、分栏比例的持久化与语义、变量编辑的主区归属。键值表幽灵行的**交互**（输入即物化、焦点停留、不提供新增按钮）也不变，但它的**空行清洗规则**会按描述列扩成两档（见上一条）——这是本变更唯一触碰既有清洗语义的地方。
- **测试**：`tests/app.test.tsx` 中断言绿色「使用中」徽标的用例需要随活跃态改版更新；请求体类型控件与表格结构的现行用例大多按 label 取值，改动后需回归。
