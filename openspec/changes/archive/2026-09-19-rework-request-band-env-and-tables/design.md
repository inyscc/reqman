## Context

主区目前是两行网格：会话标签行（`auto`）+ 内容行（`minmax(0,1fr)`），内容行在有响应时切成三列（`--split` / 5px 分隔线 / 剩余）。请求面板头、地址栏、解析预览条都渲染在左列内部的 `.request-editor` 里（`App.tsx` 的 `.request-region` → `RequestEditor` 五段式结构）。

环境激活态的唯一入口是侧栏 Environments tab，变量的编辑落在主区（ui-layout 既有要求）；环境选择器只是原生 `<select>`，没有任何「看一眼当前变量」的路径。

表格的单元格底色来自全局表单规则（`input/select/textarea` 统一给 `--panel-2` 填充 + 完整边框），表头的 `position: sticky` 已存在但没有任何表面差异。`table` 使用 `border-collapse: collapse`。

`KeyValue.description` 在存储模型、导入解析与导出序列化里都已经往返，只是没有界面入口；`ResolvedRequest.used` 在解析阶段已经算出，但没有进入 `RequestPreview`。

`KeyValue` 的空行判定（`lib/rows.ts` 的 `isEmptyKeyValue`）只看名称与值；参数表在打开请求与编辑地址栏时都会被 `lib/url.ts` 的 `alignUrlAndParams` / `withUrl` 按查询串重建，重建只按 `key` 搬运旧行的元信息。

## Goals / Non-Goals

**Goals:**

- 把「请求身份 + 地址栏 + 解析预览」抬成主区顶部一条横跨整宽的通栏带，且**不动左右分栏的任何语义**（比例、分隔线、下限、按工作区持久化）。
- 给「当前变量是什么」提供一条不改变布局、不打断请求上下文的只读路径。
- 让键值表在静默态读起来像表格而不是一排输入框，并让吸顶表头真的看得出来。
- 让环境列表的密度与激活表达与其使用方式相称（列表短、行要好点）。

**Non-Goals:**

- 不引入 GraphQL 请求体（`BodyKind` 无此类型，属能力扩展）。
- 不给 form-data 加描述列（该表的 `description` 已被文件名占用），不改数据模型与导入导出映射。
- 不做变量表的结构变更（无描述字段）。
- 不改分栏比例的持久化键与语义（仍是宽度比）。

## Decisions

### D1 请求带抬成 `.main` 网格的第 2 行，而不是重构分栏方向

`main` 的网格改为三行：`auto`（会话标签行） / `auto`（请求带） / `minmax(0,1fr)`（分栏区）。请求带是 `grid-column: 1 / -1` 的单项；`.request-region`、`.split-handle`、`.response-region` 的 `grid-row` 由 2 移到 3。

*备选与拒绝理由*：把响应区挪到下方改上下分栏——用户明确要的是「地址栏贯通、其余仍左右」，且那会推翻刚完成的分栏改动与它的持久化语义；用 `position: sticky` / 负 margin 把地址栏从列内「撑」成通栏——几何 hack 在滚动与拖拽时必然崩。

*连带决定*：`RequestEditor` 拆成「请求带」与「列内容」两块，由 `App` 显式渲染为 `.main` 的两个子元素（而不是让组件返回 fragment 由网格自动放置），因为提示块（`error`、`scriptGate`）的位置要一并决定：它们成为通栏项，顺序为 会话标签行 → 请求带 → 提示块 → 分栏区。

### D2 浮层渲染在会话标签行内，需放开该行的 `overflow`

浮层锚在环境选择器下方、覆盖内容。`.session-bar` 当前是 `overflow: hidden`，会把子元素浮层裁掉。做法：给 `.session-bar` 设 `position: relative`，把浮层作为 `.env-select` 的后代元素，并把该行的 `overflow` 放开；标签溢出仍由 `.session-tabs` 自己的 `overflow-x: auto` 兜住，因此放开不会让标签挤出可见范围。

*备选*：浮层挂到 `.main` 或 portal 到 body，用 `getBoundingClientRect` 定位——否决，多一次测量与重排同步成本，且窗口拖动/缩放时要重算。

### D3 「本请求用到的变量」由后端给出，前端不重复解析

给 `RequestPreview` 增加 `used`（`ResolvedRequest.used` 已存在，仅需送出边界）。前端据此在变量表里按名称取值，而值的三个来源（环境级、全局级、集合级）都经既有的 `variable_list(scope, owner_id)` 取得。

*备选与拒绝理由*：前端扫草稿文本里的 `{{}}`——拿不到路径变量（`:id`）与动态变量，且与「实际发出的请求」可能不一致，违反「与实际发送同源」。

*连带决定*：浮层不展示「值来自哪一层」。展示获胜层需要后端在预览结果里返回每个名字的作用域，属于另一件事；代价是集合级变量与同名的环境级变量在浮层里只能呈现一个值，按 `local > data > environment > collection > global` 的优先级由前端拼接（与解析优先级一致）。

*掩码边界*：浮层只用 `Variable.current` 的呈现值，不调用 `secret_reveal`；未揭示的 secret 天然是掩码态，浮层内不提供揭示入口。

### D4 表格改用 `border-collapse: separate`，行分隔落在单元格底边

吸顶表头要有可辨识表面，就必须让表头的背景与底边能覆盖从下方滚过的行。折叠边框在 sticky 单元格上的绘制不可靠，因此改为 `separate; border-spacing: 0`，行分隔由 `td` 的 `border-bottom` 表达，表头用不透明底 + 略重的底线。

*连带决定*：单元格内的输入控件在静默态下 `background: transparent`、边框透明，仅在 hover / `:focus-visible` 时给边界；掩码文本与徽标保持同一行高与内边距，避免行高参差（幽灵行的「行高与内容行一致」这条既有约束依赖于此）。

### D5 Description 列插在「值」之后，空行清洗拆成两档

三张键值表在名称、值之后插入描述列，幽灵行同步补一格。变量表不加列。

描述列一旦存在，「空行」就不再只有一个含义，因此把清洗拆成两档：

- **保留判定**（保存与打开）以「名称、值、描述三者皆空」为准：只写了描述的行 SHALL 被保留。否则用户在表格里写下的说明会静默消失，而这个仓库对「不丢用户输入」的要求是全局的（幽灵行整套设计都围绕着它）。
- **发出判定**（预览、发送、导出）以「名称与值皆空」为准：这类行不构成请求数据，一并剔除。这只影响本次新增的「只写了描述」的行——名称或值非空的行照旧进入发送载荷。
  
  刻意**不**剔除「名称为空但值非空」的行：Rust 侧只按 `enabled` 过滤，空名请求头会以「请求头名称不能为空」明确失败（`net/headers.rs`）。保留这个响亮失败，好过把用户填过的值静默丢掉——「静默丢数据」正是这一档判定要避免的事。

落点：`lib/rows.ts` 的两个出口（`withoutEmptyRows` 与 `cleanForSend`）各自承担一档；`lib/url.ts` 的 `alignUrlAndParams` 与 `withUrl` 在按查询串重建参数表之后，把「名称为空而描述非空」的旧行追加回去——`carryRowMeta` 按 `key` 匹配，这类行匹配不到任何查询串，没有这条例外就会在地址栏每敲一个字符时被顺手清掉。

*备选与拒绝理由*：维持单一判定并禁止「名称未填时填写描述」——用功能受限换取规则简单，且与既有「任一字段被输入即物化」的幽灵行语义直接打架；把描述做成展开式行内详情——多一层交互才能看到本来就已经存在的内容。

### D6 环境列表与集合树解耦密度

`.env-item` 的行高由 22px 提到约 32px，删除与 `.node` 同内缩同最小高度的耦合；激活态改为行首勾选标记 + 整行浅底，去掉绿色徽标与左侧强调竖条；Globals 去掉副标题；工具栏加搜索框（纯前端过滤，沿用集合树搜索「不写后端、不改选中」的既有约束）。

## Risks / Trade-offs

- [放开 `.session-bar` 的 `overflow` 可能让内容在极端窄窗下溢出到相邻区域] → 标签栏自己滚动、其余项 `flex: none`，因此溢出只可能来自新浮层本身；给浮层设最大宽度与最大高度并在内部滚动。
- [`.request-region` 等项改 `grid-row` 后，提示块与请求带出现顺序可能被网格自动放置打乱] → 任务里显式给每一项写 `grid-row`，不依赖自动放置。
- [改 `border-collapse` 会波及幽灵行的虚线下边框与既有列宽] → 回归 `tests/request-editor.test.tsx` 与浏览器测试，并目视检查幽灵行与内容行等高这条既有约束是否仍成立。
- [表头吸顶在本仓库是「CSS 已写、效果存疑」的状态] → **已实测**（`tests-browser/session-bar-and-tables.spec.ts`，本机 Chrome 150）：`position: sticky` 生效、表头确实钉住，但它钉在**内容盒**顶部——距滚动容器外沿差 8px（`.pane-body` 的 `padding-top`），滚动的行会从这条缝里穿过去，看起来就像「没吸顶」。因此 D4 除换 `border-collapse` 外，还要把吸顶位置提到容器外沿（负 `top` 或把上内边距移出滚动容器），并由该浏览器用例钉住「表头与容器外沿齐平」。
- [放开 `.session-bar` 的 `overflow` 之前，先确认现状是否已经足够] → **已实测**：在 `overflow: hidden` 下，12 个标签已能把标签栏撑到自身滚动，环境选择器与窗口按钮完整可见（同一浏览器用例的第二个 case）。因此放开 `overflow` 只影响新浮层，不会让既有控件被挤出；放开后再跑一次该用例即可确认。
- [三张表加列后，请求区被拖到最窄时列会挤] → 给描述列设最小宽度，窄列下优先压缩描述列的显示（截断），名称与值保持可读。
- [`used` 增加后，浮层的列表顺序与价值不确定] → 按解析结果里的顺序呈现，未解析项排在已解析项之后并带标记；列表较长时浮层内部滚动。
- [保留判定放宽后，只含描述的行会进入落库数据；一旦发出判定漏掉一档，空名行就会进入发送载荷并触发 Rust 侧的空名请求头失败] → 两档判定各由一条单测钉住（「不进 `cleanForSend` 结果」与「保存后重新打开仍在」），并列为同一组任务，不允许只做一半。
- [参数表的例外会让「参数列表反映查询串」不再严格成立] → 例外只覆盖没有对应查询串的行，这类行不参与发送，且 http-engine 的 delta 已把这条写成显式契约。

## Migration Plan

无数据迁移：描述数据早就在库中（导入时已写入，导出时已写出），存量集合打开即可见；「只带描述、名称与值为空」的行在存量数据里不存在（描述在此之前没有界面入口），因此放宽保留判定不会让旧数据凭空多出空行；分栏比例的存储键与语义都不变，因此旧工作区的比例照常读回；浮层与请求带都是纯视图，回滚只需撤掉本次前端改动与 `used` 字段。

## Open Questions
