## Why

主区顶部那一行今天身兼两职：它是窗口的标题栏（拖拽、双击最大化、窗口控制按钮），又是**请求的身份 header**（`所属集合名 › 方法徽标 名称输入框`，且请求名全界面只在这一处渲染）。正因为身份被托管在这唯一一格上，`ui-layout` 的「会话标签视觉壳」只能把「始终只有一个标签，不提供多标签打开」写成硬约束。

代价落在守卫上：主区只有一个草稿槽位，切换到另一个请求必然覆盖它，于是「未保存改动在切走前的守卫」被迫把**切换**列为需要三选一提示的动作——而「切走会丢东西」本来就是槽位不足的症状，不是用户意图该有的结果。

多标签把草稿按标签分开保存，于是「切换」不再丢任何东西，守卫收缩回它真正该管的范围：关闭。

## What Changes

- 顶部那一行的左侧由「单个会话标签」改为「一组会话标签」。标签集合 = 已打开的请求 + 已打开的实体脚本面板；环境编辑器不进标签——它由侧栏 tab 驱动，侧栏停在 Environments 时整条标签栏不出现（沿用既有的 `showEnvironmentEditor` 判断，不引入新状态轴）。
- **BREAKING**：标签变成**纯标签**（方法徽标 / 种类图标 + 名称，不可就地编辑）。请求名输入框、所属集合面包屑、请求级操作（另存为 / 删除）从会话标签行**下沉到请求自己的面板头**（请求侧新增；实体侧复用其已存在的 `pane-header`，把静态名称改为可编辑输入框）。`rework-visual-system-and-app-chrome` 的 D3 目标「主区顶部 chrome 由两行减为一行」被正式放弃。
- 身份下沉后，会话标签行右侧只剩环境选择器与窗口控制按钮。`window-chrome` 原本那句「不被会话标签的内容或数量挤出可见范围」由此从一个自明的要求变成需要显式满足的约束：**标签条必须是那个先收缩、先滚动的元素**。
- **BREAKING**：**切换标签不再触发未保存守卫**（草稿保留在各自的标签里），守卫改由「关闭有未保存改动的标签」触发；「切换到集合或文件夹」同理不再丢草稿。
- 新增标签的生命周期规则：同一请求只允许存在一个标签（去重）；树刷新后丢弃指向已删除请求的僵尸标签；关闭最后一个标签回到空态，而标题栏常驻（它是拖拽区）。
- 新增标签集合按工作区持久化：复用 settings 的 `scope + key=工作区 id` 约定，重启后恢复上次打开的标签与激活项。**非目标**：不持久化未保存草稿。
- 标签条溢出采用滚动（可收缩 + 隐藏滚动条的横向滚动），不做溢出下拉列表。
- 切换标签**不加动效**（沿用既有边界：每天数十次以上的操作不加过渡）。
- 键盘：`Ctrl+W` 关闭当前标签、`Ctrl+Tab` / `Ctrl+Shift+Tab` 前后切换、`Ctrl+1..9` 定位标签。

## Capabilities

### New Capabilities

无。本次不引入新能力，全部落在既有能力上。

### Modified Capabilities

- `ui-layout`：
  - 「会话标签视觉壳」改写为**多标签容器**——标签集合的构成、标签行右侧只剩环境选择器与窗口控制、标签的呈现形态（方法徽标 / 种类图标 + 名称 + 未保存圆点 + 关闭入口）。
  - 「面包屑与请求操作行」改写为**请求身份与请求级操作下沉到请求自己的面板头**。
  - 「未保存改动在切走前的守卫」收缩：**切换标签**移入「不触发守卫」清单，**关闭有未保存改动的标签**保留为触发项。
  - 新增需求：**会话标签的生命周期**（打开与去重、关闭、删除与导入后的对账、空态）。
  - 新增需求：**会话标签集合的持久化**（按工作区存取、读不懂回落默认、不覆盖未保存草稿）。

- `window-chrome`：
  - 「会话标签行拖拽区」的交互控件排除清单更新——名称输入框与请求级操作不再位于该行，而**标签本身**成为需要排除的交互控件。
  - 「页面内窗口控制按钮」的场景不再包含「标签显示环境」这一形态（环境编辑器不再占用标签行），且「不被标签数量挤出」成为实质约束而非顺带提及。

## Impact

- 前端：
  - `src/App.tsx` — 单槽位的 `draft` / `dirty` / `response` / 内层 `tab` 改为按标签持有；`useEditingSurface` 的 `request` 面改为按标签注册；`loadTree` 之后增加标签对账。
  - `src/components/RequestEditor.tsx` — 新增请求面板头，接收名称输入框、所属集合面包屑与请求级操作。
  - `src/components/EntityScriptPanel.tsx` — 已存在的 `pane-header` 中静态名称改为可编辑输入框。
  - `src/App.css` — 会话标签行与标签条样式、请求面板头样式、空态与溢出滚动。
  - 标签集合持久化的读写模块，对齐 `src/lib/layout.ts` 既有的 `settingsGet` / `settingsSet` 用法与容错纪律。
- 后端：**不动**。`settings_get` / `settings_set` 命令已存在，不需要新命令、不需要 schema 迁移。
- 测试：`tests/app.test.tsx` 中以 `session-tab` / `session-bar` / 「关闭标签」为锚点的断言需要改写；「切换到另一个请求先询问」用例语义反转（切换不再询问，关闭脏标签才询问）。
- 规格层面：`ui-layout` 与 `window-chrome` 的若干场景被替换，属 BREAKING 变更。`rodemap` 已把「多标签」列为 P1，本次不引入任何新依赖。
