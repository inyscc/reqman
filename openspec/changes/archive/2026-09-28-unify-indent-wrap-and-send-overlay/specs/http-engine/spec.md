## REMOVED Requirements

### Requirement: 格式化缩进宽度

**Reason**: 它与编辑器配置区的「缩进数」「缩进类型」是同一个用户心智里的一个设置，却被拆成两个互不相干的值：一个只作用于响应格式化（且 `JSON.stringify` 的缩进参数是数字，永远空格、无法表达 Tab），一个只作用于编辑面，而请求正文的 `Beautify` 甚至硬编码了 2 空格、连它都不读。结果是"改缩进没反应""选 Tab 也没用"在请求与响应两个方向同时成立。Postman 的形状可以作为对照：它的编辑器设置里只有一份缩进（`Indentation count` + `Indentation type`），不存在第二套"格式化缩进宽度"。

**Migration**: 缩进输出改由 code-editors「编辑器外观可配置」管辖——应用级「缩进数」（1–8）与「缩进类型」（空格 / Tab）同时驱动编辑面缩进与 JSON / XML 的格式化输出，缺省为 4 个空格。设置模态的响应呈现区不再提供该设置（见 ui-layout「设置模态的响应呈现配置」）。已持久化的旧键（响应呈现作用域下的缩进宽度）不再读取，也不做迁移：它是纯阅读偏好，把它灌回会驱动编辑面的新值属于语义污染。用户可见的变化是响应格式化输出的缺省缩进由 2 空格变为 4 空格。
