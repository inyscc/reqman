## Why

集合树当前把两个不同性质的动作揉在同一个行上：单击 = 选中实体（并打开实体脚本面板），双击 = 递归折叠/展开整棵子树。为了让「双击不选中」成立，行内单击的选中被推迟约 200ms——最高频的动作替最低频的动作付了延迟税；而「双击递归」是一条没有可见入口、无法被猜到的隐藏手势。更关键的是它的立论本身不成立：折叠一个父节点已经隐藏其整棵子树，递归折叠在屏幕上不产生任何额外效果，真正有独立效果的只有「递归展开」的一半。

用户已选定改用 VS Code 式模型——**单击行负责展开，重动作走显式入口**。本变更据此重做集合树的展开手势，并顺手把延迟归零。

## What Changes

- **BREAKING**（交互语义变更）集合与文件夹行：单击（名称文本或行内空白区）由「选中实体并打开脚本面板」改为「切换展开 / 折叠」。行内单击不再产生选中、不再切换主区、不再打开任何标签。
- 删除**双击行递归折叠 / 展开**整段手势，连同其判定与实现。递归折叠在视觉上是空操作；递归展开的需求由「单击逐层展开」承担；「把展开状态整体归零」的需求由新增的工具栏动作承担。
- 删除行内单击选中的约 200ms 去抖：单击即时生效，双击的第二次点击以 `detail === 2` 忽略以避免重复切换。键鼠手感随之统一。
- 集合与文件夹的**脚本面板入口**从「单击行」移到「⋯」菜单，新增菜单项「编辑脚本」。「重命名」保持既有行为（打开同一面板并聚焦名称输入框），因此菜单里「编辑脚本」与「重命名」的落点是同一个面。
- Collections 工具栏新增「全部折叠」控件（对齐 VS Code Explorer 的 Collapse All）：把树中全部集合与文件夹一并置为折叠。
- 请求行行为不变（单击 = 打开请求标签，即时）。
- 键盘：Enter 与单击同义——目录行 = 切换展开，请求行 = 打开。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `ui-layout`: 撤销「集合树的折叠」（其标题与全部手势条款随双击递归一并作废），由新增的「集合树的展开与折叠」替代——单击行 / Enter / 折叠箭头同义切换该节点自身的展开态；新增「集合树工具栏的全部折叠入口」承担「展开状态整体归零」；「集合树的操作入口默认隐藏」的菜单项清单新增「编辑脚本」，作为脚本面板的入口。
- `ui-polish`: 「集合树行不可文本选中」的既有场景引用了「递归折叠 / 展开手势」，随手势下线重写；禁选要求本身不变。

## Impact

- 代码：`src/components/WorkspaceTree.tsx`（行单击改为切换展开、删除去抖与递归实现、菜单加项、工具栏加控件）。`src/App.tsx` 预期无需改动——`onSelectEntity` 仍由菜单调用、`selectedEntity` 仍由激活实体标签派生，因此「会话标签与树中选中保持一致」这条既有需求字面无变化。
- 行为：展开态仍为组件内视图态（`collapsed: Set<string>`），不写后端、不跨重启保留、不影响选中与主区内容——这些既有约束全部沿用。单击由「重动作」变为「轻动作」，浏览树不再产生标签。
- 测试：`tests/app.test.tsx` 中「集合树的双击递归折叠 / 展开」用例组（5 例）整体替换；既有依赖「单击目录即选中」的断言需要相应更新。
- 无后端、无存储、无依赖改动。
