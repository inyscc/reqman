# Design

## Context

动机见 `proposal.md - Why`。与设计相关的现状：

- **取值判定与缓存已经有一处实现**：`src/lib/variableHover.ts` 的 `createVariableHoverSource` 已经按「工作区 + 激活环境 + 所属集合」惰性装载变量列表，用 `effectiveByName` 合并（集合级先放、当前作用域后放，后者覆盖前者），并缓存到本次会话。悬停提示与 `VariablesPeek` 用的都是这条口径。
- **三处编辑面都是原生 `<input>`**：地址栏（`RequestBand`）与 `KeyValueTable` 的取值列（Params / Headers，以及 Body 的 x-www-form-urlencoded 复用同一张表）。原生输入框没有编辑器的基础设施，候选浮层、光标测量、键位接管都得自己做。
- **已经有一套光标测量**：`src/lib/placeholders.ts` 的 `inputTextMeasure`（按 input 计算样式取字宽）+ 字符下标与像素偏移的互算，并为 `scrollLeft` 做补偿。候选浮层的锚点用它算，不另写一套。
- **地址栏是叠层着色 + 透明文字的 input**（`highlightUrl` 与 `pointer-events: none` 的叠层）。候选浮层不能再动那个叠层——它一旦吃到指针，光标定位与选取就废了（`show-variable-values-on-hover` 的 design D3）。
- **参数表幽灵行的回车有既定含义**：提交当前行并跳到下一行（`KeyValueTable.submitGhost`）。候选打开时回车必须先属于候选。

## Goals / Non-Goals

**Goals:**

- 键入 `{{` 就列出当前作用域内可用的变量，选中即补成完整占位符。
- 候选的取值与来源与发送同源——复用悬停提示那一处判定与缓存，不写第二套。
- 打开时不给布局带来任何变化；候选不打断输入（焦点始终在输入框里）。

**Non-Goals:**

- 不做 Body raw（Monaco）与脚本编辑器的候选：Monaco 走 `registerCompletionItemProvider`，交互与键位和原生输入框不是一回事，另一条工作线。
- 不列动态变量（`{{$guid}}` 这类）：它们没有「名字 + 值 + 来源」可言，且名单由后端固定，列表里混进来会挤掉用户真正要选的变量。
- 不做「插入后自动打开变量面板」「点击候选跳到变量定义」这类跳转。
- 不为候选新增后端命令，也不揭示 secret 的明文。

## Decisions

### D1 候选列表复用悬停提示的取值源，`secret` 只给掩码

`createVariableHoverSource` 返回的对象补一个 `candidates()`：它读的是同一份 `load()` 的映射（`Map<name, {variable, scope}>`），因此**同名遮蔽后只剩生效的那一条**、禁用条目根本不出现、作用域排序与发送一致。名称通过 `displayValue` 取当前值——secret 在这里拿到的就是后端下发的掩码。

**替代方案（否）**：候选单独走一次 `variableList` + 自己合并。两份作用域判定迟早会漂移，界面上就会出现「候选说 environment、实际发出的是 collection」。

**替代方案（否）**：候选里给 secret 显示明文。候选是"输入时随手弹出"的界面，比悬停更容易被旁人看到；明文出口仍只保留既有的两条（变量面板揭示、悬停提示）。

### D2 触发与替换范围：从光标回溯到最近的未闭合 `{{`

`suggestContext(text, caret)` 的判定：

1. 取 `text.lastIndexOf('{{', caret - 1)`，找不到即不触发。
2. `{{` 与光标之间的内容不得含 `{`、`}` 或换行——含了就说明光标不在一个正在输入的名字里（例如停在已闭合的 `{{host}}` 之后）。
3. 光标之后若紧跟 `名字字符 + }}`，替换范围延到 `}}` 之后；否则替换范围就是光标。

第 3 步是为了「改已有占位符」：光标在 `{{ho|st}}` 里选一个候选时，插进去的应是 `{{host2}}` 而不是 `{{host2}}st}}`。这也是唯一需要把替换范围向右延伸的情形。

**替代方案（否）**：只在 `{{` 刚敲下时给候选、之后不再管范围。那样「回头改名字」就得手删花括号，而人一定会忘。

**替代方案（否）**：用 `variableRanges` 的区间做替换范围。它只匹配**已闭合**的占位符，正在输入的 `{{ho` 根本不在其中——触发条件与替换范围必须是同一份判定，否则又会出现「候选弹了、插入位置却错」。

### D3 键位接管与焦点保持

- `↑` / `↓`：移动高亮项（`preventDefault`）。
- `Enter` / `Tab`：插入当前项（`preventDefault`；没有候选项时 `Enter` 不插入、让给输入框原本的行为）。
- `Esc`：收起（`preventDefault`，不再冒泡给全局 Esc）。
- 鼠标点选：条目的 `mousedown` 上 `preventDefault()`——不这么做，点击先让输入框失焦，候选会在 `click` 之前就收起，点击永远落空。

**插入后光标的位置**：受控输入框重新渲染会写回 `value`，浏览器把光标丢到末尾。因此插入用 `flushSync` 提交这次状态更新，**紧接着**同步 `setSelectionRange` 到插入之后。不用 `requestAnimationFrame`：那会让光标在下一帧才归位，用户接着打字时字符可能落到错误位置。

**幽灵行的回车**：`KeyValueTable` 的 `onKeyDown` 先问候选，`event.defaultPrevented` 为真就让位。这样「回车补全」与「回车提交并跳到下一行」不会互相抢。

### D4 浮层形态：portal + fixed，可交互

与悬停提示同构（挂在 `document.body`、`position: fixed`、空间不足时上翻），差别只有一条：候选项要能被点，所以 `pointer-events: auto`。因此它需要自己的收起规则——失焦、点击浮层之外、祖先容器滚动、光标离开该 `{{`。悬停提示的 `pointer-events: none` 是它「不抢指针」的手段，候选恰恰相反。

**替代方案（否）**：把候选做成输入框下方的常驻行。地址栏那条规格明确禁止地址栏下方出现常驻的解析结果展示区；键值表里塞一行还会推挤行高。

### D5 打开时重取一次变量列表

悬停提示的缓存策略是「本次会话内不变」，对它成立：悬停是看值，值变了也不是致命错误。候选不行——刚在变量面板加完一个变量，回来敲 `{{` 却看不到它，用户只会认为这个功能坏了。因此 `candidates()` 在**每次从关闭转为打开**时带 `refresh` 重新装载，浮层打开期间不再重复请求。

## Risks / Trade-offs

- [候选浮层挡住下方内容] → 与悬停提示同一套摆放：优先放下方、放不下上翻、左右夹在视口内；高度有上限，超出在浮层内滚动。
- [地址栏横向滚动后锚点偏移] → 锚点用与输入框同字体的测量并补偿 `scrollLeft`（与悬停命中同一条路径）；祖先容器滚动则直接收起。
- [受控输入与光标位置冲突] → `flushSync` + 同步 `setSelectionRange`；浏览器用例断言插入后紧接着键入的字符落在插入点之后。
- [回车语义被候选抢走] → 只在候选打开且存在高亮项时接管；空态下回车仍走原有行为（幽灵行提交）。
- [中文输入法组字期间弹出候选] → 组字期间不重算（`compositionstart` / `compositionend` 之间挂起），避免选字时列表跟着变。
- [每次打开多一次变量列表请求] → 只在打开那一刻取一次；这是「刚加的变量必须立刻可选」的必要代价，悬停的解析结果共用同一份缓存。

## Migration Plan

无数据迁移：不涉及存储格式与既有数据的读取含义；不新增后端命令，因此不动 `security_audit` 的命令白名单。
