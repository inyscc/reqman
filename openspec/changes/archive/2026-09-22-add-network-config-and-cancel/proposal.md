## Why

网络类的配置项目前大多只有后端能力，界面上够不着；与此同时，一次发送一旦发出就收不回来，用户只能等超时。

具体说来，`http-engine` 已经声明了「请求级网络设置」与「三级代理」，但落地程度相差很远：全局超时是一个写死的常量（`limits::DEFAULT_TIMEOUT_MS`），没有配置入口，请求级的 `Option<u64>` 只能表达"跟随缺省"与"自定义"两态；三级代理里只有请求级有界面，环境级与全局级的后端实现与前端 API 都完整，却零调用；响应体积上限与格式化阈值同样有后端、无界面。而代理凭据是**明文落库**并由命令原样回传前端，与 `storage-foundation` 已声明的「敏感值不落明文」相抵触——目前没有造成泄漏只是因为界面不存在，用户从来没有机会填过。

另一侧是一次发送的不可中断：请求走 `variables_preview → 前置脚本 → send_request → 后置脚本`，其中的网络段与脚本段都没有任何中止手段，网络段的时长又主要由超时决定。

这两半改的是同一条发送路径——超时的生效值解析与取消的令牌都落在 `send_request` 里，而配置那半的界面也贴在请求编辑器与环境编辑面上——因此一次做完，避免对同一处代码与同一片测试面动两次。

## What Changes

- **全局超时**：设置模态新增「请求」一节，全局超时以毫秒计、0 表示不限制（缺省 30 秒）。`limits::DEFAULT_TIMEOUT_MS` 的角色从"全局值"降级为"全局设置的缺省值"。
- **请求级超时改为三态**：「跟随全局 / 不限制 / 自定义」。生效值按两层解析——请求级覆盖全局；`不限制` 表示不设超时。落库形态由 `timeout_ms: Option<u64>` 变为三态结构，老请求的既有取值按读时升级保留（非空即为「自定义」）。
- **响应体积上限与格式化阈值获得界面**：两项都进「请求」一节（体积上限截断正文，格式化阈值决定超过多大不再提供结构化视图）。阈值与上限之间的关系由界面表达，不写解释性文案。
- **0 在超时这一项表示「不限制」**：界面上只写一句「0 代表不限制」，不写 Postman 那样的多行说明；超时只接受非负数。体积上限与格式化阈值不设这一档——上限是 `大响应保护` 要求的（0 会让整份正文进内存），阈值的 0 会让每一份响应都失去结构化视图。负数与读不懂的值照旧回落缺省（「一条网络设置不该因为一个坏值把每个请求都拖进立刻超时」）。
- **三级代理全部可配**：补齐环境级与全局级的代理界面（模式、地址、凭据、不走代理的主机），请求级下拉的「不使用」改为可表达**直连**——现在该选项写入 `null` 会被求解过程跳过，实际顺位到下一层，等于无法让某个请求绕过全局代理。
- **代理凭据改为加密落库**：用户名与密码走既有的 AEAD 通路（与 secret 变量、Cookie 同一条），密钥不可用时拒绝落库、绝不写明文；回传前端时只给「已设置」这一事实，不给明文。请求级代理不再保留「凭据填变量引用」这条路——该能力从未在界面上暴露过，加密取代了它的动机。
- **一次发送全程可取消**：从点击发送到写回结果，用户都能中止，覆盖前置/后置脚本段与脚本内经 `pm.sendRequest` 发出的在飞请求。取消不写响应、不报错（不弹错误条）、本次已产生的脚本输出照常保留；结果与超时、失败必须可区分，且由后端裁决，前端不抢答。
- **取消的资源收尾**：后端按发送会话撤销全部在飞令牌，并在取消路径上清理已落盘的响应正文与发送会话注册项（用 RAII 收尾，不依赖逐条补偿）。
- 排除在本变更之外：环境级超时（超时保持全局 + 请求两级）、PAC 与自动代理配置脚本、取消后自动重试、并发发送（"同时只允许一次发送"这条现状不改）。

## Capabilities

### New Capabilities

无新增能力。三项改动分别是既有三条能力在自身边界内的延伸，均为同一主题下的补充需求，不构成新的能力域。

### Modified Capabilities

- `http-engine`：请求级网络设置（超时改为两层解析）、三级代理（新增「某一层显式直连」）、新增「请求取消」；代理凭据的保护落在 `storage-foundation`，此处只做引用
- `ui-layout`：新增设置模态的「请求」与「代理」两节、请求级超时的三态控件、发送态与取消入口
- `storage-foundation`：敏感值不落明文的范围明确覆盖代理凭据

## Impact

- **代码**：`src-tauri/src/net/`（超时两层解析、取消令牌与发送会话注册表、响应落盘收尾）、`src-tauri/src/storage/`（代理凭据的加密读写与设置键）、`src-tauri/src/commands.rs` 与 `lib.rs`（新命令与注册）、`src-tauri/src/security_audit.rs`（命令白名单与明文落库守卫）、`src/components/SettingsPanel.tsx`、`src/components/RequestEditor.tsx`、`src/App.tsx`、`src/lib/scriptRuntime.ts`（脚本桥接取消）。
- **命令面**：新增取消发送的命令；`global_proxy_get` 的返回由 `ProxyConfig` 改为掩码视图，环境读取路径返回的代理同样改为掩码；代理的**写入侧**需要能区分「不改写凭据」与「清除凭据」——回传不再含明文之后，这两件事在界面上长得一样，漏掉这个区分就是一次静默的凭据丢失；`send_request` 的入参追加发送会话标识，供脚本桥与主请求共用同一会话。
- **依赖**：无新增。`tokio-util` 已在依赖树中，取消令牌不需要引入新的 crate。
- **数据**：`ProxyConfig` 的落库形态变化（密码由明文改为 AEAD 密文）。三层都没有可填凭据的入口，因此不存在用户填过的密码，不需要迁移逻辑；老行里若残留明文密码字段，因字段已改名而不会被读取，按「未设置」处理——这与本变更新立的「凭据不可读取」是两回事，后者指密文存在但解不开。
- **兼容性**：请求级超时的落库形态变化需要读时升级（老值的语义不变）。其余接口虽有形态调整（代理的读写两侧、发送入参），但 `global_proxy_get` / `global_proxy_set` / `environment_set_proxy` 从未被任何界面调用（只有测试桩引用它们），因此不构成对外部行为的破坏。
- **测试面**：后端新增超时两层解析、取消（含读正文途中取消的落盘收尾）、代理凭据不出现在数据库文件；前端新增三态超时控件、取消入口与发送态、脚本桥的取消路径。
