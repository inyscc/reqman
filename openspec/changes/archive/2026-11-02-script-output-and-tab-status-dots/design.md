## Context

Script console 与测试断言的结果都已经由运行时收集好，缺的只是呈现：`ScriptReport` 把 `entry.args.join(' ')` 直接放进 `<li>`，换行被 CSS 的默认 `white-space: normal` 吃掉；断言明细只在「脚本」标签页内部，标签页外无信号。请求侧同理——`RequestEditor` 的外层页签是纯文字，`pre_request_script` / `test_script` 写在里面不点开就看不见。集合面板的页签早有一个 `.tab-dot`（有变量 / 有脚本才点），请求侧与响应侧都没有对应物。

因此这次改动的共同点是：**数据已经齐了，只在视图层补标记，不新增状态、不改协议。**

## Goals / Non-Goals

**Goals**

- console 输出按原文呈现换行与缩进，长行在容器内折行。
- 不打开「脚本」页签也知道上一次发送的断言结果。
- 不打开 Scripts 页签也知道这条请求写了脚本。
- 三类标记共用一套视觉规格，避免"三种圆点各长一样"。

**Non-Goals**

- 不做断言计数徽章（`2/3`）、不做运行历史、不做"只看失败"过滤——它们都会把页签行当成信息面板，超出这次要解决的问题。
- 不改脚本运行时收集 console 的数据形状；换行问题不在采集层。
- 不实现"响应体正文可在脚本中修改"（另一件事，涉及 `pm.response` 的回写路径）。

## Decisions

### D1 换行交给 CSS 的 `white-space: pre-wrap`，不拆数据

console 的每个参数本来就带着换行，丢失发生在呈现层。`pre-wrap` 同时做到"保留换行"与"长行折行"两件事；`pre` 只做前者，长行会把容器撑出横向滚动。另一条路是按 `\n` 把一条输出拆成多个 `<li>`——那会把一条 console 变多条，级别与来源前缀重复十遍，反而更难读，且改坏了"一条输出就是一条记录"的语义。

配合等宽字体：多行 JSON 的缩进靠等宽才对得齐，前缀标注本来也是等宽。

### D2 状态点是页签内的 8px 圆点，不用文字徽章

页签行宽度有限，`脚本 2/3` 这样的文字会把名称挤走，且与本项目既有的 `.tab-dot` 语言不一致。颜色承担状态：绿色 `#2ea44f`（比 `--ok` 更亮，小圆点当指示灯读时不发闷，与集合面板页签同一个值），红色 `var(--danger)`。颜色之外必须另有一条线索，因此每个点都带 `role="img"` 与 `aria-label`，并补 `title`——屏幕阅读器与鼠标悬停各拿到一句"断言全部通过 / 存在失败的断言 / 已定义脚本"。这满足「不得仅靠颜色表达」的既有约束。

### D3 结果点由 `scriptAssertions` / `scriptError` 现算，不新增状态

断言与错误都是**每次发送的产物**，不是配置：持久化没有意义，重启后更不该留着上一次的红点。计算放在 `ResponsePanel` 的渲染期（`some(a => !a.passed && !a.skipped)` + `Boolean(scriptError)`），随 `scriptReport` 一起更新。

### D4 脚本抛未捕获错误按失败呈现

错误会让该脚本阶段中止，其后的断言没机会注册。此时若显示"无标记"，页签名等于告诉用户"这次没写测试"，与事实相反。因此错误优先于"有没有断言"：有错误就是红点。

### D5 请求页签的绿点按**草稿**算，不按已保存值算

请求的脚本是自动保存的，按已保存值算会让圆点比用户的输入慢一拍；用户正在写的时候正是最需要"这里有东西"这个确认的时刻。判定即 `pre_request_script` 或 `test_script` 的 `trim()` 非空——纯空白不算，与集合面板的 `hasScripts` 用同一口径。

### D6 跳过的断言不计为失败

`TestAssertion.skipped` 已经是独立字段（不是 `passed: false` 的特例）。绿点的含义定为"没有失败"，而不是"全部真的跑过"——这样跳过的用例不会把一次本该全绿的发送染红。代价是"全部被跳过"也显示绿点；这种情形在本产品里只可能由脚本显式跳过，且明细里逐条写着"跳过"，不至于误读。

## Risks / Trade-offs

- **红点描述的是上一次发送，脚本改过之后不会自动失效** → 它与「脚本」标签页里的明细同源、同生命周期：点开看到的就是那份结果。不额外造"已过期"状态，避免第二套真相。
- **`white-space: pre-wrap` 让输出里的连续空格显形** → 这正是"按原文"的含义；缩进对齐依赖等宽字体，已一并设置。
- **happy-dom 不加载样式表**，换行只能验证"文本未被改写 + 容器挂着样式钩子"，真实观感得靠人工或浏览器用例 → 在 tasks 里把这条验证方式写明，不假装单测覆盖了 CSS。
- **圆点使页签宽度增加 14px 左右** → 页签行本来就换行排布（`.tabs` 是 `flex-wrap: wrap`），且只在有内容时出现，不影响空态布局。

## Migration Plan

纯视图改动：无数据迁移、无命令变更、无存档兼容问题。回滚只需撤掉三处 JSX 与两段 CSS。
