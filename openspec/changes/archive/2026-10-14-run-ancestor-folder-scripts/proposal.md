## Why

请求挂在嵌套目录里时，**只有直接父级目录的脚本参与编排**——`phases` 只有三个槽位（集合 → 直接父级 → 请求），祖先目录的脚本永远不进数组：

```
新集合                        in collection pre script     ← 跑了
└─ 文件夹 1                   in 文件夹 1 pre script       ← 永远不跑
   └─ 文件夹 2                in 文件夹 2 pre script       ← 永远不跑
      └─ 文件夹 3             in 文件夹 3 pre script       ← 本该跑（见下）
         └─ GET 新请求1        in 请求 1 pre script         ← 跑了
```

上一个 change 当时把这件事记成了"与 Postman 相符，不改"（`openspec/changes/archive/2026-09-27-align-script-order-and-pm-objects/proposal.md` 的理由段）。本变更把那条判断**推翻**：目录上的脚本应当对它底下的一切生效，递归到根的每一个祖先目录都要执行，前置与后置都一样。目录层因此从"一个槽位"变成"一条链"。

还有一件与之纠缠、必须同修的缺陷：**请求的归属会陈旧**。本次实测的请求是先打开标签、后被拖进目录的，拖拽只写了后端与树，没有更新已打开标签里的 `folder_id`（`src/lib/treeMoves.ts` 把节点对象原样塞回树，`moveNode` 成功后也不重载 store），于是发送时 `draft.folder_id` 仍是 `null`，`folder` 被三元短路成 `null`——连那个**直接父级**的脚本都被跳过了。数据库里 `folder_id` 是对的、树里看着也是嵌进去的，只有发送路径拿到的是陈旧副本：这种"界面看不出错、行为悄悄错"的形态，正是它拖到现在才被发现的原因。

如果只把编排从三槽改成链、不动归属的来源，链就会建在一个陈旧的根上——所以两件事必须在同一个变更里做完。

## What Changes

- **目录层从槽位变成递归祖先链**：编排顺序为 集合 → 该请求所属目录及其全部递归祖先目录（由外到内）→ 请求；请求未归属任何目录时目录层不参与。前置与后置共用同一份链与同一次序。
- **归属以请求自身的当前归属为准**：发送时不再依赖标签草稿里可能陈旧的 `folder_id`，并按 `parent_folder_id` 逐级上溯取整条链（带环与深度保护，避免坏数据把发送卡死）。
- **拖拽之后归属不再撒谎**：改变归属后，持有该请求归属的副本（树节点、store、已打开标签的草稿）随之更新；主区已打开的内容与标签不因此重载。
- **错误报告能指认到具体目录**：现在层级标签是固定的三段 `['集合','文件夹','请求']`（`src/lib/scriptRuntime.ts`），链式之后"文件夹层"不再能定位问题；报告 SHALL 指明是链上的哪一个目录（同名目录按链上位置区分）。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `pm-script-runtime`:
  - 「脚本执行时机与顺序」：目录层由单层改为**递归祖先链**（由外到内），前置与后置对称；未归属目录时不编排该层。
  - 「脚本超时与错误处置」：错误报告 SHALL 指明出错的层级是集合、链上的哪一个目录、还是请求。
（不新增 `ui-layout` 的条款：可观察的行为是"脚本按请求当前的归属编排"，那一条落在 `pm-script-runtime`；树与 store 里那份陈旧副本属于实现卫生，不作为独立规格条款——见 `design.md` 的 D3。）

## Impact

- **代码**：`src/App.tsx`（发送前的脚本编排：把"取直接父级"改成"取归属并上溯整条链"；`moveNode` 之后同步归属）；`src/lib/treeMoves.ts`（移动后更新被移动请求的 `folder_id`）；`src/lib/scriptRuntime.ts`（层级的标签机制从"按固定三段索引"改为"逐段名称由调用方给出"，`runScriptPhase` 的 `scripts` 参数形态随之调整）；`src/lib/requestStore`（拖拽后重新播种受影响的请求）。
- **行为变化**：嵌套目录里祖先目录的脚本开始执行（前置与后置都执行）；目录层的报错从"文件夹层"变成具体目录名；把请求拖进目录后**不需要重开标签**即按新归属执行。
- **测试**：`tests/script-phase.test.ts`（体量最大，直接依赖三段的层级标签与 `scripts` 数组形态，需按链式改写）、`tests/app.test.tsx`（拖拽后的归属与脚本编排）、`tests-browser/` 覆盖"嵌套三层目录的请求发出后，前置与后置日志各出现五条"。
- **既有决定的推翻**：`2026-09-27-align-script-order-and-pm-objects` 里"祖先脚本不执行、与 Postman 相符"的记载被本变更取代，需在归档时一并更正那处留下的结论。
- **不受影响**：脚本沙箱本身、`pm.*` 能力的边界、超时上限、secret 掩码在脚本输出中的处理都不变；集合层与请求层的位置不变（链只是把中间那一层展开）。
