## 8. Cookie Jar

- [x] 8.3 实现 Cookie 在请求中的自动附带与匹配。reqwest `cookie_provider` 挂上应用级 jar；重定向每一跳由 reqwest 按新目标重新计算（集成测试：302 中间跳的 `Set-Cookie` 在下一跳被携带）。**实测发现并修复一个上游偏差**：`cookie_store` 组装 Cookie 头时按 BTreeMap 字典序而非 RFC 6265 §5.4 的「路径长者在前」——同名不同路径时更泛路径的值会压过更具体的值。修法是薄包装 `RfcCookieProvider`：匹配语义仍全部委托 `cookie_store`（D14 不破），只在组装头部时排序；预览调试信息（`RequestPreview.cookies` + PreviewBar 呈现）与实际发送共用同一排序，保证「看到的就是发出的」。单测覆盖：同域携带、域不匹配不携带、路径不匹配不携带、Secure 不经明文 http、host-only 不覆盖子域而域后缀覆盖。
- [x] 8.4 实现 Cookie 属性保真。行模型保留域、路径、host-only、安全/仅协议标记与有效期；保存→落库→重载→匹配全链路逐一验证（HttpOnly+Secure+域后缀+路径各就各位），同名同路径不同 host-only 不互覆，同名不同路径按请求路径分别选择（RFC 排序下更具体者在前）。密钥不可用时持久化被拒绝但内存 jar 仍可用（降级态取向与 secret 一致）。**实机修正（本轮）**：上述降级语义当时只落在 jar 层，**发送路径上却是致命的**——`send_request` 里 `jar.ensure_loaded(...)?` 与 `jar.sync_to_db(...)?` 把 `SecretStoreUnavailable` 直接上抛，于是在无 DBus 会话的环境（纯 SSH、容器；实机报「系统凭据库不可用：Platform secure storage failure: DBus error: Failed to connect to socket /run/user/1000/bus」）**所有请求都发不出去**，而 secret 变量的取向只是降级为 `Unreadable`、不影响其它功能。修法：这两处把该错误码按降级处理——不装载持久 Cookie、不落库，记一条 warn 日志后照常发送；其它错误照旧上抛。根因是「降级态只写在 jar 层，没写到调用点」。用例：jar 级 `degraded_key_provider_does_not_fail_load_or_sync`（降级既不写入也不删除库里那条）+ 端到端 `unavailable_key_store_does_not_break_sending`（不可用凭据库下发送成功、零 Cookie 行、同一 jar 的下一跳仍自动携带）。另把凭据库报错文案改为说明「受影响的只有 secret 与 Cookie 的持久化」，并写入 README 已知限制。**附带记录**：改文案顺带暴露一条既有用例的写法问题——`keyring_provider_never_panics_and_never_leaks` 原本断言「错误文本里不含 `secret` 这个词」，而它想表达的是「不含明文/密钥材料」；文案一旦解释影响范围就会被误伤。已改为断言真正的不变量：不含 ≥40 字符的连续字母数字片段（32 字节密钥的 base64 形态），并要求提示可读（含「凭据库」）。验证：`cargo test --lib` 273 项通过、`npx tsc --noEmit` 无错、前端 60 项通过。
