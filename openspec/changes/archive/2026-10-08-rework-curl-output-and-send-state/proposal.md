## Why

curl 导出当前用 `--data-raw`、且请求体保留用户的多行排版，粘贴到只认 `-d` 的终端或需要单行命令的场景会直接失效或难用；同时"发送中"是应用级单例状态，一次发送会波及其它请求标签（按钮被禁、底栏误报、无法保存），也无法同时发送两条请求。

## What Changes

- **curl 数据体参数改用 `-d`**，仅当值以 `@` 开头时退回 `--data-raw`（保住既有「命令 SHALL 可直接执行」的要求——`-d '@...'` 会被 curl 当成文件名去读）。
- **curl 命令布局成为一项配置**：单行 / 多行，按「折行」同款两层解析——应用级缺省（缺省多行）+ 请求级三态（跟随全局 / 单行 / 多行，随请求保存）；两种布局共享同一份参数。
- **curl 内嵌正文压缩改按内容判定**：尝试把 raw 正文作为 JSON 紧凑化，成功即压缩、失败即原样（与语言选择无关，语言选为 text 而内容是合法 JSON 时同样压缩）；算法与 body 的 `Minify` 同一压缩语义且不重排键序；空正文或不合法 JSON 一律原样、不告警。开关同样照「折行」两层：应用级缺省（缺省＝压缩）+ 请求级三态。
- **命令旁的开关全部取消**：布局与压缩都只保留应用级 + 请求级两处配置入口，cURL 动作行回到「重新生成 / 复制」两个动作——配置散落成一次性开关，用户改过一次下次进来又变回去，无从察觉。
- **命令文本块始终软折行**：单行布局下整条命令常是一个不含空格的超长 token（URL 全是查询串），只按词边界折行照样横向溢出；因此固定允许在 token 内部断开，且不提供折行开关。
- **发送态按请求标签隔离**：每条请求各自持有自己的「发送中」状态与取消出口；`busy` 不再由发送置位，只留给保存与改名。
- **允许多条请求同时在飞**（并发条数不限）；后端 `SendRegistry` 与脚本沙箱已按会话隔离，无需改动。
- **底栏「发送中…」改为按「是否存在任一条在飞发送」派生**，顺带修掉「保存 / 改名时底栏也显示发送中」这一既有误报。
- **关闭正在发送的标签会撤销该次发送**。
- **并发写同名变量 = 后完成者覆盖先完成者**，作为已知差异记录（并发固有语义，非缺陷）。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `postman-interchange`：「导出 curl」——数据体参数改用 `-d`（`@` 开头时回退 `--data-raw`）、内嵌正文压缩改为**按内容**判定（成功即压缩、失败即原样，与语言选择无关）、命令布局由生效设置决定（缺省多行）。
- `ui-layout`：「cURL 快照标签」取消命令旁的布局与压缩开关，并让命令文本块**始终软折行**（超长的单行命令不再横向溢出，且不提供折行开关）；新增「cURL 命令布局」与「cURL 正文压缩」两项设置，都按「折行」同款两层解析（应用级缺省 + 请求级三态）；「地址栏」与「发送中的响应区反馈」由单数「一次发送」改为「该请求的一次发送」，并允许并发；底栏状态改为按在飞发送派生；新增「请求级错误提示」规定发送与脚本错误的归属。
- `http-engine`：「请求取消」允许应用内同时存在多个发送会话（多个 `attempt_id` 在飞），取消仍精确到单个会话。
- `pm-script-runtime`：「脚本来源的可执行性门禁」——门禁归属到触发它的那条发送，并发时互不覆盖，「允许执行并继续」作用于触发它的那一条。

## Impact

- **Rust**：`src-tauri/src/interchange/curl.rs`（`-d` 与 `@` 回退、body 压缩、布局）、`src-tauri/src/commands.rs`（`curl_export` 接收并解析压缩设置）；新增/复用一个应用级设置键承载压缩缺省。
- **前端**：`src/App.tsx`（发送态改为 per-tab 容器、取消出口按会话、底栏派生、关标签撤销、错误与脚本门禁按发起它的标签归属）、`src/components/CurlSnapshot.tsx`（单行/多行与压缩开关）、`src/components/RequestEditor.tsx`（Settings 标签新增压缩行、cURL 动作行）、`src/lib/types.ts`（请求设置新增压缩三态字段）、`src/components/BottomBar.tsx`（状态文案）、设置模态与应用级缺省读取处。
- **测试**：`src-tauri` 的 curl 单测、`tests/request-editor.test.tsx`、`tests/app.test.tsx`。
- **可观察的连带变化**：导入 / 导出模态里「导出 curl」的输出随本改动一并变化（压缩生效、缺省多行布局），与请求编辑器的入口保持一致。
- **不改动**：`code-editors` 能力（cURL 快照仍为纯 `<textarea>`，不升级为代码编辑器）；后端发送与脚本沙箱的并发模型（已就绪，无需改动）。
