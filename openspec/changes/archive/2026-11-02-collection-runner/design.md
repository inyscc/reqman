## Context

「发送」这条流水线（解析 → 前置脚本 → 合并改写 → 发送 → 后置脚本）此前整段写在 `App.tsx` 的 `performSend` 里，与标签状态、发送态、错误归属缠在一起。运行器要按顺序跑 N 条，且必须与单条发送**完全一致**——脚本要跑、请求头/正文的改写要生效、门禁要问、取消要撤。在运行器里另写一遍必然分叉，因此先把它抽成 `src/lib/requestExecution.ts`，让两条入口共用。

界面侧没有"一组请求"的概念：树是导航，标签是编辑面，谁都不负责"把这一组跑一遍并汇总"。运行器补的正是这一层。

## Goals / Non-Goals

**Goals**

- 集合 / 目录面板头一个入口，打开就是这一组的名单，默认全选。
- 顺序执行、可设间隔、可随时停止。
- 每条的结果一眼可辨（通过 / 失败 / 出错 / 停止），并能下钻看 console 与断言明细。
- 执行语义与单条发送一致：脚本、改写、变量、门禁、取消一条不少。

**Non-Goals**

- 不做运行历史、不做定时/CI 触发、不做多环境批跑（data file / iteration）：那是另一层编排，先把"跑一遍并看见结果"做对。
- 不做断点续跑：停止就是停止，重跑从第一条开始。
- 不把结果写回标签或落库：运行产物只属于这次运行的面板。

## Decisions

### D1 抽出 `executeRequest`，两条入口共用

`App.tsx` 的 `performSend` 里，真正与界面无关的部分（解析、三级脚本、头/体的差异合并、发送、后置脚本）原样搬进 `src/lib/requestExecution.ts`，产出 `RequestExecutionOutcome`（响应 / 错误 / console / 断言 / 脚本错误 / 门禁 / 取消）。界面侧的留痕（写标签、报错、门禁提示、收尾）留在 `App`。

这样运行器拿到的就是"发送"这一件事的完整语义，无需也不允许另写一份。抽取的验收标准是既有的 269 条端到端用例全绿——它们覆盖脚本编排、门禁、取消、改写与错误归属。

### D2 名单在打开时拍平并冻结

`collectRunRequests` 按树上的顺序深度优先，目录就地展开（与用户看到的顺序一致，也与 Postman 的 run collection 一致）。名单在**打开运行器时**算好：运行期间拖动、删除、改名都不影响这一轮——否则跑到一半换了一份名单，结果与"我勾的那几条"就对不上了。

### D3 间隔放在两条之间，而不是每条之前

第一条立刻发，最后一条跑完不再等：否则"跑完了"与"还在转圈"之间会多出一段没有意义的空白。间隔的等待可被打断——停止时立刻醒来，不必干等完 5 秒。

### D4 结果由执行结果折出来，不另存状态机

`statusOfOutcome` 把一次执行折成一行：取消 → 门禁 → 请求失败 → 断言失败 / 脚本报错 → 通过。判定次序有意义：取消排最前，因为它不该被算成失败（spec: http-engine「请求取消」）；没有写断言的一条算通过——它没断言可挂，不等于它挂了。

明细不做第二套呈现：断言表与 console 直接复用 `ScriptReport`，与响应区的「脚本」页签同一个组件，两处口径不会分叉。

### D5 门禁在开跑前问，不在跑到第一条时问

脚本门禁是**按集合**生效的（spec: 脚本来源的可执行性门禁）。运行器打开时先查一次，未获准就先让人选「允许执行」还是「不执行脚本，仅发送请求」；选之前运行按钮不可用。若等到第一条才发现，用户已经看着进度条跑起来了，却被告知"要先去另一个地方点一下"。

### D6 关闭面板即停止

标题栏的 ×、Esc、点遮罩都会直接卸载面板。收尾因此挂在卸载上：置停止标志、唤醒间隔等待、撤掉在飞的那一条。否则界面没了、请求还在发——这是最糟的一种"看起来停了"。

### D7 运行的是已保存的请求，与打开的标签草稿无关

名单来自树，树反映的是库里那一份。打开的标签若有不保存的改动，运行器不采用它——一次运行要能被复现，"刚才跑的是改了两个字的那份草稿"不是一个可复现的结果。

### D8 版面分三列：跑什么 / 跑成什么样 / 怎么跑

名单、明细、设置各占一列，从左到右读，正好答完一次运行的三个问题。设置**不**并进名单上方的工具栏：那会把"勾选哪些"和"多久发一条"挤成同一行控件，窄窗口下先散架的也是它；独占右列之后，主按钮有了固定落点，进度也归到设置旁边——"怎么跑"和"跑到哪了"本来就是一件事。

行内不放目录路径：400px 宽的名单里再加一列，名字与路径会互相截断，两边都读不成句子。上下文挪到明细头部（那里有整行宽，也正好是"我要看这一条"的时候）。状态列在**有结果之后**才定宽——没跑的时候空占一百多像素，名字白白被挤窄。

## Risks / Trade-offs

- **抽取流水线动了发送这条主路径** → 风险最高的一处，因此不改行为、只搬位置，并用既有端到端用例当验收；抽取后全量 656 条通过。
- **结果不落库** → 关掉面板就没了。这是有意的：它属于"这次运行的观察"，不是文档；需要留存的人可以把 console 复制出去。
- **默认全选** → 对"只想跑一条"的人是多余的勾选。但运行集合的常见意图就是全跑；取消个别比逐条勾选省事。
- **间隔只支持毫秒输入** → 够表达"限流留 200ms"这类需求；不做秒级单位切换，避免两个输入框表一件事。
- **运行器不展示响应正文** → 这次要回答"哪几条挂了、为什么"，正文留给响应区；把正文也塞进面板会让名单一眼看不全。

## Migration Plan

纯新增功能 + 一次无行为变更的抽取。无数据迁移、无命令变更。回滚需撤掉运行器入口与三个新文件，并把流水线搬回 `App.tsx`（或保留抽取、只删入口）。
