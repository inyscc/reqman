# Design

## D1 判据是「这个实体的标签开着没有」，不是点击次数

需求是「没有标签页时点击先打开标签页，已经打开过就像以前一样」。唯一稳定的判据只能是**标签是否存在**（`entityTabId(kind, id)` 是否在 `tabs` 里），因为：

- 点击次数不可靠：关掉标签再点又回到「第一次」；顶替预览标签也会让计数失真。
- 时间间隔更糟：要引入双击判定的延时，直接违背「单击即时生效」。
- 选中态不成立：选中 ≠ 标签开着（预览标签会被顶替，切到别的标签时选中态也会变）。

`App` 因此把「已打开的实体标签 key 集合」通过 `openEntityTabs` 传进树，树在渲染时算出本行的 `tabOpen`。这份判断只用于**手势语义**，不用于渲染（标签开没开不改变行的样子）。

## D2 标签 key 的拼法只留一处

`entityTabId` 原本是 `App.tsx` 里的私有函数；树现在也要拼同一个 key 去查集合。两处各写一份 `entity:${kind}:${id}` 迟早会失配（改了一处忘了另一处就是「永远查不到」的静默失效），所以把它移到 `src/lib/sessionTabs.ts` 导出，`App` 与树共用。

## D3 顺序：先打开，再切换

`onSelectEntity` 是异步的（标签不存在时要先 `folderGet`），而 `onToggle` 是同步的视图态。代码里先调 `onSelectEntity` 再按 `tabOpen` 调 `onToggle`，`tabOpen` 则取**本击派发前**的那份集合——所以「第一次单击」不会因为同一击里刚插入的标签而被误判成「已打开」，不会出现「打开的同时又收起来」。

## D4 行内箭头保持不变

箭头仍是「只折叠、不打开」：它 `stopPropagation`，只调 `onToggle`。用户想「不打开面板、只收子树」时有明确入口；想「边看边收」就点行（标签已开时）。

## D5 搜索态继续冻结折叠

搜索态下 `onToggle` 本来就是空操作，`collapseAll` 与箭头也被禁用。行单击即使标签已打开，也只是打开面板——折叠集合一个字都不写，清空搜索后仍回到用户原来记住的展开状态。
